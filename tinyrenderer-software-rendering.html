이 글 읽는 법위→아래가 곧 “한 장의 그림이 그려지는 순서”입니다. 파란 상자와 그림만 따라가도 전체 흐름이 잡히고, 검은 코드와 수식은 “⌄ 더 깊이” 안에 접어 뒀으니 궁금할 때만 펼치세요.

한 줄 요약

“GPU가 안에서 하는 일”을 500줄로 직접 만든 렌더러입니다. 그래픽스 라이브러리를 하나도 안 쓰고, 수학·이미지 저장까지 전부 손으로 짰어요. 입력은 3D 모델 파일, 출력은 그림 한 장.

큰 흐름

모델을 읽고 → 점들을 카메라 화면 좌표로 변환 → 삼각형을 픽셀로 하나씩 채우고 → 앞에 있는 것만 남기고(가리기) → 빛을 계산해 색을 정합니다. 딱 그래픽 카드가 하는 일의 축소판이에요.

가장 영리한 부분

삼각형 채우기를 행렬 하나로 해결합니다. 한 줄로 “뒤집힌 삼각형 버리기 + 너무 작은 삼각형 버리기”를 동시에 하고, 한 번의 곱셈으로 “이 점이 삼각형 안이야?”를 판정합니다.

공부용으로 최고

작아서 전부 눈에 보입니다. 대신 프로덕션용은 아니에요 — 안티에일리어싱·부드러운 텍스처 보간 같은 건 “원리를 드러내려고” 일부러 뺐습니다.

01 · 무엇을 하는 코드인가

“GPU를 쓰는 법”이 아니라 “GPU가 하는 일”

🧩

쉽게 말하면보통은 그래픽 카드(GPU)가 3D를 알아서 그려줍니다. 이 코드는 그 GPU 안에서 벌어지는 일을 사람이 읽을 수 있게 손으로 재현한 거예요. 그래서 외부 라이브러리를 하나도 안 쓰고, 결과도 화면이 아니라 framebuffer.tga 이미지 파일 한 장으로 나옵니다.

파일은 딱 다섯 개, 각자 한 가지 일을 맡습니다. 이 표가 글 전체의 지도예요.

파일 지도 — 각 파일이 “한 장의 그림”에서 맡은 역할
파일맡은 일쉬운 설명
geometry.h수학벡터·행렬 계산(3D의 기본 연산)
tgaimage.*이미지그림 파일 읽고 쓰기, 점 하나 색 칠하기
model.*모델3D 모델(OBJ)과 표면 그림(텍스처) 불러오기
our_gl.*파이프라인좌표 변환 · 삼각형 채우기 · 앞뒤 가리기
main.cpp지휘자빛 계산(셰이더) 정의 + 전체 순서 진행

유일한 선택적 부품은 “여러 픽셀을 동시에 계산”하는 OpenMP 한 줄뿐. 없어도 (조금 느리게) 그대로 돌아갑니다.

02 · 준비물: 수학과 이미지

벡터·행렬도, 그림 파일도 직접 만들었다

📐

쉽게 말하면3D를 다루려면 벡터·행렬 계산(점을 옮기고 돌리는 수학)이 꼭 필요합니다. 보통은 라이브러리를 쓰지만, 이 렌더러는 그것마저 geometry.h에 직접 만들었어요. 그림 파일을 읽고 쓰는 코드(tgaimage)도 손수 짰습니다.

핵심만 알면 됩니다. 벡터는 “점의 위치나 방향”, 행렬은 “점들을 한꺼번에 옮기고 돌리는 변환표”예요. 뒤에 나오는 “좌표계 여행”이 바로 이 행렬 곱하기의 연속입니다.

더 깊이 — 템플릿 벡터/행렬, 재귀 행렬식, 그리고 왜 invert_transpose가 중요한가

geometry.h는 크기를 컴파일타임에 정하는 vec<n>(double 저장)과 mat<행,열>(각 행이 vec) 템플릿에 내적·행렬곱을 연산자 오버로드로 얹었습니다. 재밌는 부분은 행렬식을 템플릿 메타프로그래밍 재귀로 푼다는 점(dt<n>이 라플라스 전개로 dt<n-1>을 부르고 dt<1>이 종료). 여인수로 invert·invert_transpose·transpose를 일반 차원으로 구현합니다.

invert_transpose()가 이 렌더러의 숨은 주역입니다. 딱 두 곳에서 결정적으로 쓰여요 — 법선(표면이 향한 방향) 변환, 그리고 05장의 무게중심 좌표 계산. 동차좌표용 embed/proj 헬퍼는 없고, vec4의 중괄호 초기화(위치는 w=1, 방향은 w=0)와 .xy()/.xyz()가 그 역할을 합니다.

tgaimage는 18바이트 packed TGA 헤더, BGRA 색상 순서, 무압축과 RLE(런렝스) 양쪽 읽기/쓰기, get/set 픽셀, 상하·좌우 flip을 제공합니다. 색이 BGRA로 저장된다는 사실이 뒤의 노멀맵 디코드·스페큘러 샘플의 근거가 됩니다.

03 · 3D 모델 읽어오기

모양(OBJ)과 표면 그림(텍스처)

📦

쉽게 말하면3D 캐릭터는 수많은 삼각형으로 이루어진 껍데기(모양)와, 그 위에 입히는 표면 그림들(텍스처)로 되어 있습니다. 이 단계는 그 두 가지를 파일에서 읽어오는 일이에요.

  • 모양(OBJ 파일) — 점 위치(v), 표면 그림 좌표(vt), 표면이 향한 방향(vn), 그리고 “이 세 점이 한 삼각형(f)”이라는 정보를 읽습니다. 삼각형만 지원해요.
  • 표면 그림 3장 — 파일 이름 규칙으로 자동으로 딸려 옵니다: 디퓨즈(원래 색), 노멀맵(울퉁불퉁한 요철), 스페큘러(어디가 반짝이는지).
  • 텍스처 좌표 뒤집기 — 파일과 화면의 위아래 기준이 달라서, 읽을 때 세로(V) 좌표를 1−v로 뒤집어 맞춥니다. 안 그러면 무늬가 상하로 뒤집혀요.
🌐

노멀맵이 뭔가요?평평한 삼각형에 “울퉁불퉁해 보이는 착시”를 주는 그림입니다. 그림의 빨강·초록·파랑(RGB) 값이 곧 그 지점이 향한 방향(x·y·z)이에요. 이걸 읽어 빛 계산에 쓰면, 삼각형 몇 개로도 정교한 요철이 있는 것처럼 보입니다.

더 깊이 — 인덱스 배열, 최근접 샘플링, 노멀맵 디코드

정점·uv·법선 개수가 서로 다를 수 있어 3개의 평행 인덱스 배열(facet_vrt/tex/nrm)로 코너를 참조합니다. OBJ 인덱스는 1부터라 --로 0-기반 변환. 텍스처 샘플링은 전부 최근접 이웃(bilinear·UV 래핑 없음)이라 uv가 면 안에 있다고 가정합니다.

노멀맵 디코드: 텍셀(BGRA)을 {R,G,B}로 재배열 후 ×2/255 − 1로 [0,255] 바이트를 [-1,1] 방향 벡터로 바꾸고 정규화합니다. 읽는 것은 _nm_tangent.tga(접선공간 노멀맵)이며, 접선 벡터 자체는 모델에 저장하지 않고 06장의 프래그먼트 셰이더가 매 픽셀 계산합니다.

04 · 좌표계 여행 (사진 찍기)

모델의 한 점이 화면 픽셀이 되기까지

📷

쉽게 말하면카메라로 사진을 찍는 과정과 똑같습니다. ①물체를 카메라 앞에 놓고(모델뷰) → ②원근감을 넣고(퍼스펙티브) → ③화면 크기에 맞춰 자릅니다(뷰포트). 3D의 한 점이 이 여행을 거치면 2D 화면의 한 픽셀 위치가 됩니다.

정점 셰이더가 각 점을 이 여행에 태우고, 그 결과로 나온 화면 삼각형을 다음 단계(05장)가 픽셀로 채웁니다.

더 깊이 — 각 행렬이 실제로 하는 계산
공간변환내용
오브젝트→눈ModelViewlookat이 만든 카메라 기저 회전 × 이동. center가 눈공간 원점이 됨.
눈→클립Perspective행렬 [3][2]=−1/f 하나로 w = 1 − z/f. f는 카메라~center 거리.
클립→NDC÷ w네 성분을 w로 나눔. 여기서 원근 왜곡 발생.
NDC→화면Viewportw/2·h/2 스케일 + 오프셋. .xy()만 취함.

참고: 흔한 오해와 달리 vertex()는 셰이더 인터페이스의 가상함수가 아니라 구체 셰이더에 있어 main에서 직접 호출됩니다(검증 단계에서 확인).

05 · 삼각형을 픽셀로 칠하기

감싼 네모 안을 훑으며 “안이야?” 묻기 + 앞엣것만 남기기

🔲

쉽게 말하면삼각형을 화면에 칠하려면 어떤 픽셀이 삼각형 안인지 알아야 합니다. 방법은 단순해요 — 삼각형을 감싸는 네모(바운딩 박스)를 잡고, 그 안의 픽셀마다 “너 삼각형 안이야?”를 물어 맞으면 칠하고 아니면 건너뜁니다.

💡 무게중심 좌표 = “세 꼭짓점을 얼마씩 섞었나”

한 점을 “A를 α, B를 β, C를 γ만큼 섞은 것”으로 표현한 게 무게중심 좌표(α,β,γ)입니다. 셋 다 0 이상이면 삼각형 안, 하나라도 음수면 밖이에요. 게다가 이 비율을 그대로 쓰면 세 꼭짓점의 색·좌표·깊이를 부드럽게 섞을(보간) 수 있습니다.

이 렌더러의 영리함: 스크린 세 점을 담은 행렬 하나를 뒤집기만 하면 그 곱셈이 곧바로 (α,β,γ)를 줍니다 — 변마다 도는 반복문 없이 한 방에.

🃏

그 다음 — 앞엣것만 남기기(z-buffer)여러 삼각형이 겹치면 카메라에 가까운 것만 보여야 합니다. 그래서 픽셀마다 “지금까지 가장 가까운 깊이”를 적어두고(z-buffer), 더 가까운 게 오면 덮어씁니다.

더 깊이 — 실제 rasterize 코드와 “왜 행렬 뒤집기가 무게중심을 주나” 
void rasterize(const Triangle &clip, const IShader &shader, TGAImage &fb) {
    vec4 ndc[3]    = { clip[0]/clip[0].w, ... };            // ① 원근분할: clip → NDC
    vec2 screen[3] = { (Viewport*ndc[0]).xy(), ... };      // ② NDC → 스크린 좌표

    mat<3,3> ABC = {{ {screen[0].x, screen[0].y, 1}, ... }};   // 세 점을 '행'으로
    if (ABC.det() < 1) return;   // ③ 뒤집힌 삼각형 + 1px 미만 버리기 (한 줄!)

    auto [bbminx,bbmaxx] = std::minmax({screen[0].x, ...});  // ④ 바운딩 박스
#pragma omp parallel for                                    // 픽셀 병렬 처리
    for (int x=...; x<=...; x++)
      for (int y=...; y<=...; y++) {
        vec3 bc = ABC.invert_transpose() * vec3{x,y,1};  // ⑤ 무게중심을 한 방에
        if (bc.x<0 || bc.y<0 || bc.z<0) continue;   // 삼각형 밖 → 건너뜀
        double z = bc * vec3{ndc[0].z, ndc[1].z, ndc[2].z};  // ⑥ 깊이 섞기
        if (z <= zbuffer[x+y*fb.width()]) continue;   // ⑦ 앞엣것만 (클수록 가까움)
        auto [discard, color] = shader.fragment(bc_clip);   // ⑧ 색 계산
        if (discard) continue;
        zbuffer[x+y*fb.width()] = z;  fb.set(x, y, color);
      }
}

our_gl.cpp — 주석·클램프는 축약, 핵심 로직은 원문 그대로

왜 invert_transpose()가 무게중심을 주나: ABC는 세 점을 행으로 담았으니 “점을 열로 담은 행렬 M”의 전치, 즉 ABC = Mᵀ. 그런데 invert_transpose()는 (Mᵀ)⁻ᵀ = M⁻¹을 돌려줍니다. 무게중심 (α,β,γ)는 정의상 M·(α,β,γ) = (x,y,1)을 만족하므로 M⁻¹·(x,y,1)이 바로 답입니다 — 그래서 한 번의 곱셈으로 끝.

z-buffer: std::vector<double>를 −1000(먼 곳)으로 초기화, 클수록 가까움 규약. 깊이 z는 원근분할 뒤 NDC의 z를 스크린 무게중심으로 섞은 값입니다(색·uv 보간엔 원근보정 무게중심을 따로 씀 — 미묘하지만 원근 텍스처가 안 뭉개지는 핵심).

06 · 빛으로 색 정하기

요철을 흉내내고(노멀맵) 밝기·반짝임을 더한다(Phong)

💡

쉽게 말하면픽셀 하나의 최종 색은 “원래 표면색 × 받는 빛의 양”입니다. 빛의 양은 세 가지를 더해요 — 기본 밝기(ambient) + 정면으로 받는 빛(diffuse) + 반짝이는 하이라이트(specular). 여기에 노멀맵으로 표면 요철까지 흉내내면 진짜처럼 보입니다.

  • 기본 밝기(ambient) — 그늘도 새까맣지 않게 깔아주는 최소 밝기(0.4 고정).
  • 정면 빛(diffuse) — 표면이 광원을 정면으로 볼수록 밝아짐(면의 방향 · 빛 방향).
  • 반짝임(specular) — 빛이 카메라 쪽으로 튕겨 나올 때 생기는 하이라이트. 스페큘러 맵으로 “어디가 얼마나 반짝일지” 조절.
  • 요철(노멀맵) — 평평한 삼각형이라도 노멀맵의 방향값으로 울퉁불퉁하게 빛을 받게 만듦.
🧭

Darboux 프레임이란노멀맵의 방향값은 “표면에 붙은 좌표계” 기준이라, 실제 눈 기준 방향으로 바꿔줘야 합니다. 그 변환에 필요한 접선 방향을, 삼각형의 모서리와 텍스처 좌표 변화로 매 픽셀 즉석에서 계산하는 게 Darboux 프레임입니다. (접선을 모델에 미리 저장하지 않는다는 게 포인트.)

더 깊이 — 실제 프래그먼트 셰이더 코드(Phong + 노멀맵) 
std::pair<bool,TGAColor> fragment(const vec3 bar) const {
    mat<2,4> E = { tri[1]-tri[0], tri[2]-tri[0] };            // 눈공간 삼각형 두 모서리
    mat<2,2> U = { uv[1]-uv[0], uv[2]-uv[0] };                // 대응 uv 증분
    mat<2,4> T = U.invert() * E;                              // E=U·T 풀어 접선/종법선
    mat<4,4> D = { normalized(T[0]),                          // tangent
                   normalized(T[1]),                          // bitangent
                   normalized(nrm[0]*bar[0]+...),             // 보간 법선
                   {0,0,0,1} };                                // Darboux 프레임
    vec4 n = normalized(D.transpose() * model.normal(uv));   // 노멀맵 → 눈공간 법선
    vec4 r = normalized(n*(n*l)*2 - l);                     // 반사벡터 r = 2(n·l)n − l
    double ambient  = .4;
    double diffuse  = max(0., n*l);                        // 램버트
    double specular = (.5+2.*sample2D(model.specular(),uv)[0]/255.)
                     * pow(max(r.z, 0.), 35);              // r.z: 카메라가 +z축
    TGAColor c = sample2D(model.diffuse(), uv);              // 원래 표면색
    for (int ch : {0,1,2})
        c[ch] = min(255, c[ch]*(ambient + diffuse + specular));
    return {false, c};
}

작아서 다 보이는 그래픽스 교과서

배울 점

추상화가 딱 GPU만큼만 있습니다. 좌표 변환 행렬, 정점/픽셀 셰이더, z-buffer, 값 보간 — 실제 그래픽스 API 개념이 500줄에 1:1로 대응돼, “래스터화가 뭐냐”를 코드로 만져 볼 수 있어요.

영리한 지점

수학을 이해하면 코드가 짧아집니다. 행렬 하나(invert_transpose)가 법선 변환과 무게중심 계산 두 곳에 재활용되고, 판별식 한 줄이 컬링 둘을 겸합니다.

한계(의도된)

프로덕션용은 아닙니다. 안티에일리어싱·부드러운 텍스처 보간·클리핑이 없고 삼각형 OBJ만 받습니다. 전부 “원리를 드러내려고” 뺀 것들이라, 오히려 공부엔 이상적이에요.

한마디로 “GPU가 삼각형 하나를 픽셀로 바꾸는 과정을, 숨은 라이브러리 없이 전부 눈으로 볼 수 있게 만든 코드”입니다.

분석 방법: 저장소를 얕은 클론 후 3개 병렬 리더(수학·이미지 / 모델·텍스처 / 파이프라인·셰이딩)로 코드를 읽고, 래스터화·z-buffer·좌표계·셰이딩 수식은 별도 검증 에이전트가 our_gl.cpp·main.cpp를 직접 대조했습니다.
